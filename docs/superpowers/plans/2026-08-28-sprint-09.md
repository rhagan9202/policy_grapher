# Sprint 9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the product read the duties DoD writes by position rather than by modal verb, stop paying for pages that state no duty, and clear two carried defects.

**Architecture:** `Modality` gains a sixth member, `ASSIGNED`, for a duty imposed by position. Because a value naming no word cannot be checked against the passage, it is guarded structurally instead: the schema requires a named actor, and a shared validation helper requires the chunk's section to be titled RESPONSIBILITIES. That title is currently parsed and thrown away, so the chunker starts keeping it as a non-identity attribute — it must never enter `_chunk_id` or `obligation_id`.

**Tech Stack:** Python 3.14, FastAPI, Pydantic v2, Neo4j, pytest, uv. Ollama `llama3.1:8b` behind the local extraction adapter.

**Spec:** [docs/superpowers/specs/2026-08-28-extraction-coverage-design.md](../specs/2026-08-28-extraction-coverage-design.md)

## Global Constraints

- **`section_title` is hashed into nothing.** `section_path` is already hashed into `_chunk_id` and `obligation_id`; adding the title to either re-keys every chunk and obligation in the graph and orphans every recorded human decision.
- **Three existing checks will fail when `Modality` gains a member, and none may be loosened:** `test_the_gold_set_covers_every_modality_the_schema_allows`, `test_every_modality_the_schema_allows_has_a_weight`, `test_the_modality_weights_are_exactly_what_was_decided`. Each is satisfied by supplying what it asks for. Task 5 lands all three together for this reason.
- **`ASSIGNED` is exempt from the modality-word rule by construction, never by an exception list.** Write the rule as "if the modality names a word", deriving the word set from the enum.
- **A refused item costs itself, not its chunk** (ADR-030). Route every refusal through the existing `on_drop` channel; never raise so that a whole chunk is rejected.
- **`PROMPT_VERSION` must be bumped in the same commit as any prompt text change.** It participates in the cache key; an in-place edit leaves the cache serving results from a prompt that no longer exists.
- **A new test that passes on its first run is not believed.** Watch every test fail first, and mutate the thing it guards before accepting it. Three sprints running produced a guard that did not guard, and the tell was identical each time.
- **Run `uv run pytest -m "not integration"` from `backend/` before every commit.** Lint rides along as `test_lint.py`.
- Do not commit `.env` or generated secrets.

### Task 1: A chunk starting on a section join reports the right page

Implements [STORY-075](../../backlog/stories/STORY-075-a-chunk-on-a-section-join-is-attributed-to-the-right-page.md). Independent of everything else in this plan — no model, no database, no rebuild.

**Files:**
- Modify: `backend/src/policy_grapher/chunking.py:194-205`
- Test: `backend/tests/test_chunking.py`

**Interfaces:**
- Consumes: nothing.
- Produces: nothing other tasks rely on.

**Background the implementer needs.** `_page_at(lines, offset)` maps an offset in a section's joined text back to a page. The text is `"\n".join(line for _, line in lines)`, so each line consumes `len(line) + 1` — its own length plus the single newline `join` inserted. `cursor + len(line)` is therefore the index **of that newline**, and the current `offset <= cursor + len(line)` claims it for the line *before* it.

Two different bugs produce this symptom, and the test must distinguish them:

1. The boundary is wrong — the fix is `<` and the chunk keeps its leading newline.
2. The leading newline is wrong — no chunk should begin on a join at all, and the offset question dissolves.

- [ ] **Step 1: Write the failing test**

Add to `backend/tests/test_chunking.py`:

```python
def test_a_chunk_starting_on_a_section_join_reports_the_page_its_text_is_on():
    """STORY-075. `_page_at` claimed the join's newline for the line before it.

    The offset handed to `_page_at` is the index of the newline that `"\\n".join`
    inserted between two lines. The text at that offset belongs to the line
    *after* it, so the page reported must be that line's page.
    """

    lines = [(4, "first line"), (5, "second line")]
    join_offset = len("first line")  # the index of the inserted newline

    assert _page_at(lines, join_offset) == 5
```

- [ ] **Step 3: Fix the boundary**

In `backend/src/policy_grapher/chunking.py`, change `_page_at`'s comparison from `<=` to `<` and record the decision in the docstring:

```python
    cursor = 0
    for page_number, line in lines:
        # `<`, not `<=`: `cursor + len(line)` is the index of the newline that
        # `"\n".join` inserted, and the character at that offset opens the *next*
        # line. STORY-075 decided this is the boundary bug rather than a
        # leading-newline bug — a chunk may legitimately begin on a join, and when
        # it does its text is the following line's, so its page is that line's page.
        if offset < cursor + len(line):
            return page_number
        cursor += len(line) + 1
    return lines[-1][0] if lines else 1
```

```python
    """STORY-099, and sprint 8's retrospective action.

    STORY-086 compares the routers' declared paths against `client.ts` and calls
    neither, which is correct for its purpose and blind to a route that does not
    resolve. `GET /documents/duplicates` 404'd for an entire sprint underneath a
    green suite for exactly that reason.

    Only an unroutable path answers 404, so 404 is the whole assertion.

    from policy_grapher.dependencies import get_driver
    from policy_grapher.main import app

        client = TestClient(app, raise_server_exceptions=False)

        f"{sorted(unreachable)}. A route declared after a path that matches it — "
        f"`/{{slug}}` before `/duplicates` — is the usual cause; FastAPI matches in "
```

### Task 3: The chunker keeps the title of the section it is in

**Files:**
- Modify: `backend/src/policy_grapher/chunking.py`
- Test: `backend/tests/test_chunking.py`

**Interfaces:**

- Produces:
  - `heading_title(line: str) -> str | None` — the title on a heading line, or `None`.
  - `Chunk.section_title: str | None` — the title of the outermost element of this chunk's `section_path` that has one.

**Background the implementer needs.** `NAMED` is `^(?P<kind>CHAPTER|SECTION|APPENDIX|ENCLOSURE)\s+(?P<id>[\dIVXA-Z]+)\b`, so the path element for `SECTION 2:  RESPONSIBILITIES` is `"SECTION 2"` and the title is discarded. Two formats put the title in two places, verified against `data/samples`:

| Format | Heading line | Title location |
| --- | --- | --- |
| Modern (`500001p.pdf`) | `SECTION 2:  RESPONSIBILITIES` | Same line, after the colon |
| Older (`850001_2014.pdf`) | `ENCLOSURE 2` | The next non-blank line — `RESPONSIBILITIES` |

The modern format also emits the heading as a running header with a page number appended — `SECTION 2:  RESPONSIBILITIES 11` — so a trailing number must be stripped.

**`section_title` must not enter `_chunk_id`.** It is an attribute of the chunk, not part of its identity.

```python
# The title on a heading line, in the format that writes one there:
# "SECTION 2:  RESPONSIBILITIES". A trailing page number belongs to the running
# header the modern format repeats on every page, not to the section's name.
TITLED = re.compile(
    r"^(?:CHAPTER|SECTION|APPENDIX|ENCLOSURE)\s+[\dIVXA-Z]+\s*[:.]\s*(?P<title>.+?)\s*\d*$"
)


def heading_title(line: str) -> str | None:
    """The title this heading line names, or None if it names none.

    ADR-033's guard is the section, and the section's own words are the only
    honest way to know what a section is. `NAMED` captures the heading's *id* and
    discards everything after it, so `SECTION 2:  RESPONSIBILITIES` reaches
    `section_path` as `"SECTION 2"` — a position, saying nothing about what sits
    there. This recovers the rest of the line.

    The older format writes the title on the *next* line instead, so a bare
    `ENCLOSURE 2` correctly yields None and `chunk_pages` reads on.
    """
    stripped = line.strip()
    if DOT_LEADER.search(stripped):
        return None
    match = TITLED.match(stripped)
    if not match:
        return None
    title = match["title"].strip()
    return title.upper() if title else None
```

```python
class Modality(StrEnum):
    """How a duty was imposed — by a word, or by position.

    Still closed, and for the original reason: SHALL misread as SHOULD downgrades
    a binding duty to advice, silently, so an adapter that invents a value must
    fail loudly.

    Five members name the word the passage used. ASSIGNED names none, because
    DoD writes its responsibilities sections as a role heading followed by
    lettered third-person verbs and grades their force nowhere — the duty is
    imposed by *position*. ADR-033 widened what this enum records to admit that:
    it is no longer "the word the document used" but how the duty arrived.

    The member records the mechanism, not the force. Ask `is_binding` for force.
    """

    SHALL = "SHALL"
    MUST = "MUST"
    WILL = "WILL"
    SHOULD = "SHOULD"
    MAY = "MAY"
    ASSIGNED = "ASSIGNED"


# The members that quote a word from the passage. Derived by subtraction, never
# listed: a sixth *word* added later joins this set automatically, whereas a
# hand-kept list is how a word modality silently escapes the rule below.
WORD_MODALITIES = frozenset(Modality) - {Modality.ASSIGNED}

BINDING = frozenset({Modality.SHALL, Modality.MUST, Modality.WILL, Modality.ASSIGNED})
```

Then restate the validator:

```python
    @model_validator(mode="after")
    def _modality_word_is_in_the_statement(self) -> ExtractedObligation:
        """If a modality names a word, the statement must contain that word.

        Restated by ADR-033 rather than given an exception. ASSIGNED falls
        outside this rule because it names no word — by construction, not by
        being listed — and an exception list is how such a check rots.
        """
        if self.modality not in WORD_MODALITIES:
            return self
        if not re.search(rf"\b{self.modality.value}\b", self.statement, re.IGNORECASE):
            raise ValueError(
                f"statement does not contain its modality {self.modality.value!r}: "
                f"{self.statement!r}"
            )
        return self

    @model_validator(mode="after")
    def _an_assigned_duty_names_its_actor(self) -> ExtractedObligation:
        """ADR-033's schema half of the structural guard.

        A positional duty is an assignment *to somebody*. Without an actor there
        is no position, and ASSIGNED becomes the escape hatch that puts section
        headings back in the graph as duties.
        """
        if self.modality is Modality.ASSIGNED and not (self.actor or "").strip():
            raise ValueError("an ASSIGNED obligation must name the actor it is assigned to")
```

In `backend/src/policy_grapher/extraction/schema.py`:

```python
# The word a section's own title uses when it assigns duties to offices. Matched
# against the title the *document* wrote, not against a list of sections we
# expect to exist — which is what keeps this from being the keyword list
# STORY-098's second criterion forbids.
RESPONSIBILITIES = re.compile(r"\bRESPONSIBILIT(?:Y|IES)\b", re.IGNORECASE)


def is_responsibilities_section(section_title: str | None) -> bool:
    """Whether a section's own title says it assigns responsibilities.

    ADR-033 guards ASSIGNED structurally because it cannot be guarded lexically:
    a value naming no word cannot be checked against the passage the way the
    other five now are. A document whose format hides its section titles yields
    None here and simply never produces an ASSIGNED obligation, which is the
    correct conservative failure.
    """
    return bool(section_title and RESPONSIBILITIES.search(section_title))


def validate_extracted(item: dict, *, section_title: str | None) -> ExtractedObligation:
    """Schema validation, plus the part of ADR-033 that needs the section.

    One function because there are two callers — the local adapter when the model
    answers, and the cache when it replays a hit — and a rule living in only one
    of them is a rule a cache hit walks around.

    Raises `ValidationError` and never a bare `ValueError`, because both callers
    catch `ValidationError` to drop one item and keep the rest (ADR-030). A
    different exception type escapes that handling and rejects the whole chunk.
    """
    obligation = ExtractedObligation.model_validate(item)
    if obligation.modality is Modality.ASSIGNED and not is_responsibilities_section(
        section_title
    ):
        raise PydanticCustomError(
            "assigned_outside_responsibilities",
            "ASSIGNED is only valid in a section whose title names responsibilities; "
            "this chunk's section is {section_title}",
            {"section_title": section_title or "untitled"},
        )
    return obligation
```

If raising a `ValidationError` directly proves awkward, wrap the check in a small Pydantic model instead — **the constraint is that the exception is caught by the existing `except ValidationError` in both callers.** Verify that with the ADR-030 test in Step 1, not by inspection.
