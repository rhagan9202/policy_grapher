# DI-2 — Design

**Date:** 2026-08-20 · **Status:** Draft, awaiting review

Design for Development Increment 2: the semantic substrate that turns the DI-1 citation graph
into a policy knowledge graph, proven by **impact triage** — answering *"a higher-level policy
changed; which of our policies are affected, and how urgently?"*

Unlike the [DI-1 completion design](2026-08-13-di-1-completion-design.md), this document
describes behaviour no existing spec covers. It is the input to a `SPEC-002`, not a substitute
for one — per [CONVENTIONS](../../CONVENTIONS.md), new behaviour earns a `specs/SPEC-NNN-*.md`.
Write SPEC-002 from this design when the implementation plan is drawn.

## Goal

[SPEC-001](../../specs/SPEC-001-di-1-policy-grapher.md) proved the pipeline: file on disk →
Neo4j → API → UI. The graph it produces is **bibliographic** — 438 `:Document` nodes joined by
one untyped `:REFERENCES` edge, carrying names and citation structure and nothing else.

The [vision](../../planning/vision.md) asks a question that graph cannot answer: *"what else is
affected if this instruction changes?"* Answering it needs three things DI-1 does not have —
the text of the documents, the obligations inside that text, and a way to represent one version
of a document superseding another.

DI-2 builds those three things and proves them with one user-facing deliverable.

## What is already true

- **DI-1 is complete** — 18 of 18 stories, closed 2026-08-13. PDF ingestion (STORY-016) and
  `:Source` provenance (STORY-037) landed afterwards.
- The graph stores **no document text at all**. `:Document` carries `slug` and `name`. PDFs are
  read into memory, regex-scraped for citations, and the text discarded.
- There is **no embedding, vector index, full-text index, or model call** anywhere in the
  backend. The dependency set is `fastapi`, `pydantic`, `pydantic-settings`, `neo4j`, `pypdf`,
  `uvicorn`.
- Neo4j is pinned at `2025.10`, which supports native vector indexes. Nothing uses them.
- `POST /query` is unrestricted, WRITE-routed Cypher with no auth ([ADR-004](../../specs/adr/ADR-004-unrestricted-cypher-in-di-1.md)).
- 197 backend tests; the 90 non-integration tests pass without a database.

## Decisions taken before this design

| Question | Decision |
| --- | --- |
| Scope | Substrate + impact triage. Coverage matrices and drafted amendments are DI-3 and DI-4. |
| Hierarchy | Public Law / US Code → DoD issuance → DLA issuance → J8 procedure |
| Corpus | Public 4-tier financial slice; tier 4 (J8) deferred behind authentication |
| Substrate shape | Bibliographic spine + rebuildable derived overlay |
| Deployment target | Hosted / multi-user eventually — so security is designed for, not retrofitted |
| Security sequencing | Phase 0 gate: nothing else starts until it lands |
| `IMPLEMENTS` links | Machine-proposed, human-approved, with a summary for review |
| Embeddings | Local model, not a hosted embedding service |

## Ontology

The central move: **DI-1's graph does not migrate.** `:Document` already carries stable
identity — unique slug, unique name, `:Source` provenance — so it *is* the instrument identity.
Versions hang off it. Every DI-1 invariant and every existing test survives untouched.

### Canonical — DI-1, unchanged

```
(:Document {slug, name})
(:Document)-[:REFERENCES]->(:Document)
(:Source {id, kind, filename})-[:DESCRIBES]->(:Document)
:External  = no incoming :DESCRIBES        # ADR-007's rule, verbatim
```

### Canonical — new in DI-2

```
(:Document)-[:HAS_VERSION]->(:DocumentVersion {effective_date, checksum, source_uri})
(:DocumentVersion)-[:SUPERSEDES]->(:DocumentVersion)
(:DocumentVersion)-[:ISSUED_BY]->(:Authority {slug, name})
(:Entity {slug, name, kind})
(:LinkDecision {key, verdict, actor, at, rationale})
```

`:SUPERSEDES` is the relationship type [ADR-006](../../specs/adr/ADR-006-relational-facts-live-on-typed-edges.md)
already named as direction. `:LinkDecision` is canonical rather than derived for the reason
given under *Human decisions* below.

### Derived — droppable, rebuildable, never hand-edited

```
(:DocumentVersion)-[:HAS_CHUNK]->(:Chunk {text, page, section_path, embedding})
(:DocumentVersion)-[:MANDATES]->(:Obligation {id, modality, actor, statement,
                                              deadline, conditions, confidence})
(:Obligation)-[:ANCHORED_IN]->(:Chunk)
(:Obligation)-[:IMPLEMENTS_PROPOSED]->(:Obligation)
(:Obligation)-[:IMPLEMENTS]->(:Obligation)
(:Obligation)-[:APPLIES_TO]->(:Entity)
(:Obligation)-[:ENFORCED_BY]->(:Authority)
(:Change {id, kind, summary})-[:AFFECTS]->(:Obligation)
(:Change)-[:FROM_VERSION|:TO_VERSION]->(:DocumentVersion)
```

### Three properties that carry the design

**`modality` is the ranking axis.** `SHALL` / `MUST` / `SHOULD` / `MAY` is the difference
between a binding obligation and guidance. It is the most important extracted field and the
reason triage output can be ordered by consequence rather than by string similarity.

**`ANCHORED_IN` makes answers checkable.** Every obligation traces to a chunk with a page and a
section path. No triage row, answer, or future drafted amendment can be produced without a
citation, because the citation is structural rather than something the model is asked to
remember.

**Obligation ids are deterministic**, not random:

```
id = hash(version_slug, section_path, normalized_statement)
```

Without this, every re-extraction orphans every human decision. See below.

### Human decisions live in the canonical layer

The overlay is droppable. If approvals lived in it, every re-extraction would silently discard
every review anyone had ever done — a failure that produces no error and is noticed late.

So `:IMPLEMENTS_PROPOSED` (machine-authored) and `:IMPLEMENTS` (human-promoted) are **separate
relationship types**, not one type with a status property. Triage traverses `:IMPLEMENTS` only,
which means an unreviewed inference cannot be presented as fact by construction rather than by
remembering to filter. A canonical `:LinkDecision` records each verdict — approvals *and*
rejections, because a rebuild that resurrects a link someone already rejected is worse than one
that forgets it.

Rebuild replays decisions onto freshly proposed links by matching the decision key. That only
works because obligation ids are deterministic.

## Phase 0 — the security gate

Nothing else starts until this lands. Everything after it assumes it.

| Work | Why it gates |
| --- | --- |
| STORY-019 authentication, per-user identity | [ADR-004](../../specs/adr/ADR-004-unrestricted-cypher-in-di-1.md) prerequisite; supplies the `actor` on every `:LinkDecision` |
| STORY-024 query constraints | Read-only routing, timeout, row cap on `POST /query` |
| Secrets out of the committed `.env` | The Neo4j password is public by construction today |
| ADR-008, ADR-009, ADR-010 | ADR-001 and ADR-004 each name their own revisit conditions. This is those conditions arriving; ADR-010 records the `.env` decision changing. |

`POST /query` is the sharp edge. It is WRITE-routed raw Cypher, unauthenticated, behind
`allow_origins=["*"]`. Once a model generates queries against it, a prompt-injected document
becomes arbitrary graph mutation — and the corpus is, by definition, documents supplied from
outside. DI-2 splits it: `POST /query` becomes read-only and constrained; mutation moves to an
authenticated admin route.

## Corpus

```
Tier 1   US Code Titles 10 / 31, OMB Circulars A-123 / A-136
Tier 2   DoD 7000.14-R (DoDFMR), DoDD 5105.22 (DLA charter)
Tier 3   DLA issuances (publicly released)
Tier 4   J8 financial management procedures        — deferred behind authentication
```

Two risks on the record rather than discovered later:

**The existing extractor will not survive the move.** `sources/pdf.py` is five regex stages
tuned to the DoD issuance `REFERENCES` section. The DoDFMR is ~15 volumes with a
chapter/paragraph structure nothing like it. The pinned ratchet floors stay valid for what they
cover; DoDFMR needs its own fixtures and its own floors. That is real work, not configuration.

**Chunking policy text is not generic chunking.** Fixed-size windows split obligations away
from their conditions and scope qualifiers — precisely the failure that produces confidently
wrong compliance answers. Chunking follows the document's section hierarchy, and `section_path`
is carried through, because it is also what makes a citation legible to a human reviewer.

> **Assumption:** the tier-1 through tier-3 documents named above are publicly available and
> redistributable for development use. Confirm before building fixtures against them.

## Ingestion and versioning

A file resolves to `(:Document)-[:HAS_VERSION]->(:DocumentVersion)` keyed by `effective_date`
plus a content checksum.

- Re-ingesting an identical file stays a no-op. DI-1's idempotency invariant is preserved.
- Ingesting a **newer edition** creates a second version and a `:SUPERSEDES` edge. That is the
  event which drives triage.
- Ingest stays uniformly additive, per [ADR-007](../../specs/adr/ADR-007-sources-describe-documents.md).
  Nothing demotes or un-describes.

`document_name_unique` and `document_slug_unique` remain on `:Document`, which is why versions
must be their own nodes rather than differently-named documents. Two editions of one instrument
share one `:Document`.

## Extraction

The LLM is a **port**, not a dependency:

```
ObligationExtractor:  (chunk_text, section_path, taxonomy) -> Obligation[]
```

Adapters: a local small instruct model for development, a hosted provider for production. Four
consequences follow.

**Capability is not uniform, so the interface is the floor.** Structured output, prompt caching,
batch pricing, native citations, long context — none are universal. Adapters declare optional
capabilities; the contract does not depend on them. This costs the batch and cache economics as
*guarantees*; they return as adapter-specific optimizations.

**Schema validation lives in our code.** A Pydantic model validates every extraction result on
every adapter. Native constrained decoding — JSON-schema output, or a GBNF grammar on a local
runtime — is an optimization behind the same boundary, never the correctness boundary. This is
what keeps behaviour identical across a swap.

**The eval ratchet is the swap gate.** One gold obligation set, one runner, per-adapter recorded
floors, following the pattern `test_extraction_ratchet.py` already establishes. A provider swap
is legal only when it clears the floors — so *swappable* is a tested property. Development
floors on the local model may sit lower than production floors; promotion has to clear the
real bar.

`precision`, `recall`, and `modality accuracy` are pinned **separately**. A `SHALL` misread as
`SHOULD` silently downgrades a binding obligation to advice, and an aggregate score hides it.

**Extraction results are cached** by `(chunk_content_hash, adapter_id, prompt_version)`, so
rebuilds are cheap and adapter comparisons are like-for-like.

The deterministic regex extractor is untouched. SPEC-001 requires it to stay model-free, and
obligation extraction is an additive second path over stored text — not a replacement for
citation extraction.

## Retrieval

Embeddings are a port too, defaulting to a local model (BGE- or E5-class). Beyond keeping
development offline and reproducible like the testcontainers suite, it is the only option that
still works when tier-4 material arrives — sending controlled material to a hosted embedding
service would be a hard stop, and discovering that in DI-3 means re-embedding the corpus.

A local default also preserves `architecture.md`'s *"no external network services, APIs, or
model providers"* posture for development and test. Hosted providers become opt-in
configuration rather than a broken invariant.

**`embedding_model` and `dimensions` are recorded on the index and refused on mismatch.**
Vectors from two embedders are not comparable, and a silent swap does not error — it returns
quietly wrong neighbours indefinitely.

Retrieval fuses three signals:

```
query
 ├─ vector     → Neo4j native vector index on :Chunk.embedding
 ├─ full-text  → Neo4j full-text index; exact designators ("DoDI 5000.88",
 │               "s.14(2)") are lexical, and embeddings handle them badly
 └─ graph      → traverse IMPLEMENTS / MANDATES / REFERENCES from seed hits
        ↓
   fuse, rerank by modality weight and tier distance
```

The graph leg is what makes this graph RAG rather than RAG beside a graph. A vector search for
*"notification deadline"* finds chunks that say deadline; the traversal finds the org clause
that *implements* the statute the deadline came from.

### Prompt injection

The corpus is documents from outside, fed to a model. Three rules:

1. **Extracted obligations are data, never instructions.** The extraction call is given no
   tools, so document text has nothing to actuate.
2. **No generated raw Cypher against a write-capable endpoint.** The question-answering layer
   selects from parameterized query templates over a read-only route; it does not author graph
   queries.
3. **Operator instructions travel in the provider's system channel**, not interpolated into
   user-turn content — user-visible content now includes ingested document text.

## Change detection, triage, and review

```
1. DIFF       obligations(v_old) vs obligations(v_new)  ->  :Change
                matched on deterministic obligation id;
                MODIFIED when the id matches but statement / modality / deadline differ

2. PROPAGATE  (:Change)-[:AFFECTS]->(o)<-[:IMPLEMENTS]-(ours)
                ranked by modality weight x change kind x tier distance

3. REVIEW     unreviewed :IMPLEMENTS_PROPOSED edges form a queue:
                higher obligation + citation | our clause + citation |
                rationale + confidence | approve / reject / edit
                -> writes :LinkDecision, promotes to :IMPLEMENTS
```

Impact triage is one traversal:

```cypher
MATCH (c:Change)-[:AFFECTS]->(higher:Obligation)
      <-[:IMPLEMENTS]-(ours:Obligation)
      <-[:MANDATES]-(v:DocumentVersion)<-[:HAS_VERSION]-(d:Document)
RETURN d.name, ours.statement, higher.modality, c.kind
ORDER BY modality_weight(higher.modality) DESC
```

The model appears twice in this section: proposing candidate links, and writing the one-line
rationale a human reads before deciding. The triage itself is traversal — which is why it is
explainable, cheap to test, and cannot hallucinate an obligation into the result set.

## Testing

Extends the existing shape rather than replacing it:

- **Integration tests** against throwaway Neo4j via testcontainers, per SPEC-001's testing
  floors. Mocking the driver stays rejected.
- **Extraction ratchet** extended to obligations, with separate precision / recall / modality
  floors, per adapter.
- **Rebuild idempotency** — drop the derived layer, re-extract, replay decisions, assert the
  graph is equivalent and every approval survived. This single test is what makes *rebuildable
  overlay* a fact rather than an intention.
- **Version and supersession tests** — two editions of one instrument coexist; diff produces
  the expected `:Change` set.
- **Retrieval tests** — embedding-model mismatch is refused; hybrid fusion returns the graph-leg
  result that neither vector nor full-text alone would reach.

## Sequencing

Roughly the order in which each piece becomes testable:

1. Phase 0 security gate
2. Schema migration — versions, authorities, entities
3. Text storage — section-aware chunking with page and `section_path`
4. Extraction port, local adapter, obligation ratchet
5. Typed links, `:LinkDecision`, review queue
6. Diff and propagation
7. Triage UI and grounded question answering

## Out of DI-2 scope

Deferred, not excluded — each earns its place the same way, by an ADR when revisited:

- **Coverage matrices** — the absence of `:IMPLEMENTS` as a first-class view (DI-3)
- **Drafted amendments** — generating redlined clause text (DI-4)
- **Tier-4 J8 material** — behind authentication
- **Entity resolution** — near-duplicates are still flagged, never merged (STORY-031)
- **Multi-format ingestion** — DOCX and XLSX (STORY-035, STORY-036) are independent of this work

## Open questions

- **Which authority issues an obligation** is sometimes stated and sometimes structural. Where
  `ISSUED_BY` cannot be derived, it is left absent rather than guessed.
- **Modality taxonomy across tiers.** US Code, DoD issuances, and DLA issuances do not use
  `shall` identically. The gold set should settle this empirically before the taxonomy hardens.

> **Assumption:** one human reviewer is sufficient for `IMPLEMENTS` approval — there is no
> second-approver or segregation-of-duties requirement. Confirm before the review queue is built;
> it is cheap now and expensive later.

- **CI remains unbuilt.** Testcontainers means any pipeline needs Docker-in-Docker. DI-2 adds a
  model-dependent test suite on top. This is the increment where the absence starts to cost.
